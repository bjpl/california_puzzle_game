## Technical Decisions

### Decision 1: Bottom Sheet vs. Modal for Mobile Regions Panel

**Context**: Needed to adapt desktop sidebar regions panel for mobile without blocking map view

**Options Considered**:

1. **Bottom Sheet** - Pros: Modern pattern, partial screen coverage, preserves context. Cons: Requires animation implementation
2. **Full-Screen Modal** - Pros: Simple implementation, maximum space. Cons: Loses map context, feels heavy
3. **Drawer from Side** - Pros: Familiar desktop pattern. Cons: Awkward on mobile, covers too much
4. **Keep Sidebar** - Pros: No changes needed. Cons: Blocks map, poor mobile UX

**Decision**: Bottom Sheet with FAB trigger

**Rationale**: Bottom sheets are the industry standard for mobile contextual content (Google Maps, Apple Maps, ride-sharing apps). They provide excellent UX by showing content while maintaining map context. The 60vh height limit ensures users can still see and interact with the map. FAB placement at bottom-right follows mobile conventions for secondary actions.

**Trade-offs**: More complex implementation than modal, but significantly better UX. Animation requires careful performance consideration, but 300ms duration keeps it snappy.

---

### Decision 2: Dropdown vs. Horizontal Tabs for Explore Mode Navigation

**Context**: Horizontal tabs in Explore mode overflow on mobile devices

**Options Considered**:

1. **Dropdown Select** - Pros: Space-efficient, familiar mobile pattern. Cons: Less visual, requires tap to see options
2. **Scrollable Horizontal Tabs** - Pros: Maintains desktop pattern. Cons: Hidden tabs not discoverable, awkward scrolling
3. **Stacked Vertical Tabs** - Pros: All visible, no overflow. Cons: Takes too much vertical space
4. **Accordion** - Pros: Compact when collapsed. Cons: Heavy interaction pattern for simple navigation

**Decision**: Dropdown Select with clear labeling

**Rationale**: Dropdown selects are the standard mobile pattern for navigation when space is limited (YouTube mobile, Twitter mobile, etc.). They're immediately familiar to mobile users and don't require teaching new interaction patterns. The vertical space savings is significant, allowing more room for actual content. Clear labeling ensures users understand what content they're viewing.

**Trade-offs**: Less immediately visible than tabs, but this is acceptable given mobile users expect this pattern. The space savings far outweigh the slight decrease in discoverability.

---

### Decision 3: 44px Minimum Touch Target Standard

**Context**: Need to ensure accessibility and usability on mobile devices

**Options Considered**:

1. **44px Minimum (Apple HIG)** - Pros: Proven accessibility standard, comfortable for all users. Cons: Takes more space
2. **48dp Minimum (Material Design)** - Pros: Android standard. Cons: Even larger than Apple
3. **40px Minimum (Custom)** - Pros: Saves space. Cons: Below accessibility standards, harder to tap
4. **Variable Sizes** - Pros: Flexibility. Cons: Inconsistent UX, accessibility issues

**Decision**: 44px minimum touch target standard (Apple Human Interface Guidelines)

**Rationale**: 44px is the established accessibility standard from Apple's Human Interface Guidelines, validated through extensive user research. It ensures comfortable tapping for users with varying motor abilities and finger sizes. This standard is widely adopted across the industry and meets WCAG accessibility guidelines. While it requires more vertical space, the improved usability and accessibility are essential for a quality mobile experience.

**Trade-offs**: Larger touch targets require more vertical space, potentially increasing scrolling. However, this is acceptable as it significantly improves usability and ensures the app is accessible to all users, including those with motor disabilities.

---

### Decision 4: Comprehensive vs. Incremental Mobile Optimization

**Context**: Study Mode has 5 distinct tabs that needed mobile optimization

**Options Considered**:

1. **Comprehensive (All at Once)** - Pros: Consistent experience, efficient implementation. Cons: Larger change set, more testing needed
2. **Incremental (Tab by Tab)** - Pros: Smaller changes, easier to review. Cons: Inconsistent experience, multiple PRs
3. **Priority-Based** - Pros: Focus on high-impact areas first. Cons: Some tabs remain unoptimized longer
4. **Minimal (Most-Used Only)** - Pros: Smallest effort. Cons: Incomplete solution, confused users

**Decision**: Comprehensive optimization of all 5 tabs in single commit

**Rationale**: Mobile users expect consistent experiences across all features. Implementing all optimizations at once ensures no tab feels neglected or broken. The 543-line change is manageable because all tabs share common patterns (bottom sheets, responsive padding, touch targets). Users won't encounter jarring inconsistencies when switching between tabs. Single implementation also allows for code reuse and consistent patterns.

**Trade-offs**: Larger commit requires more thorough testing, but the benefit of immediate consistency across all study mode features outweighs this. The comprehensive approach also allows for shared components and utilities to be created once and used everywhere.
