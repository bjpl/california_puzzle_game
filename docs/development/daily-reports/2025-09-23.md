## Technical Decisions Made

### 1. Design System Architecture

```
Decision: Separate educational design CSS from main styles
Rationale:
  ✓ Clear separation of concerns
  ✓ Easy to maintain/update themes
  ✓ Better performance (conditional loading)
  ✓ Reusable across features

Structure:
  styles/
    ├── globals.css           (base styles)
    ├── educational-design.css (Study Mode theme)
    └── animations.css         (shared animations)
```

### 2. Game State Strategy

```
Decision: Use sessionStorage for state persistence
Rationale:
  ✓ Survives page refreshes
  ✓ Clears on tab close
  ✓ No server needed
  ✓ Fast read/write

Alternative Considered:
  ❌ localStorage: Too persistent
  ❌ Context only: Lost on refresh
  ❌ Server storage: Unnecessary complexity
```

### 3. Label Layering Solution

```
Decision: Separate SVG group for labels above counties
Rationale:
  ✓ Clean separation
  ✓ Easy z-index control
  ✓ Performance benefit
  ✓ Maintains drag/drop functionality

Implementation:
  <svg>
    <g id="counties">{counties}</g>
    <g id="labels">{labels}</g>
  </svg>
```
