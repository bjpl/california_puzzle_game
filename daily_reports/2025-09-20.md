## Technical Decisions Made

### 1. Multi-Resolution Geodata Strategy

```
Decision: 4 geodata resolution levels
Rationale:
  ✓ Mobile optimization (ultra-low)
  ✓ Tablet performance (low)
  ✓ Desktop quality (medium)
  ✓ High-DPI displays (high)

Implementation:
  • Automatic detection
  • Progressive loading
  • 95% size reduction (ultra-low vs high)

Performance:
  Mobile:  20KB geodata (0.3s load)
  Desktop: 194KB geodata (0.8s load)
  High-DPI: 966KB geodata (2.1s load)
```

### 2. Component Architecture

```
Decision: Feature-based organization
Rationale:
  ✓ Scalability
  ✓ Maintainability
  ✓ Clear boundaries
  ✓ Easy testing

Structure:
  components/
    ├── game/          (core gameplay)
    ├── map/           (rendering)
    ├── study/         (educational)
    ├── ui/            (shared UI)
    └── [feature]/     (isolated features)
```

### 3. State Management

```
Decision: Zustand over Redux
Rationale:
  ✓ Simpler API
  ✓ Less boilerplate
  ✓ Better TypeScript support
  ✓ Smaller bundle size

Store Structure:
  gameStore:     Core game state
  studyStore:    Educational mode
  soundStore:    Audio management
```

### 4. Testing Strategy

```
Decision: Vitest over Jest
Rationale:
  ✓ Faster execution (5x)
  ✓ Better Vite integration
  ✓ ESM support
  ✓ Watch mode performance

Coverage Goals:
  • Unit: 85%+
  • Integration: 90%+
  • Accessibility: 95%+
```
