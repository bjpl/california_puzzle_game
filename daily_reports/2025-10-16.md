## Technical Decisions

### Decision 1: TouchEvent changedTouches vs touches Array

**Context**: Mobile gesture tests failing because touchend events have empty touches array

**Options Considered**:

1. **Check changedTouches first** - Pros: Follows spec, works for all touch events Cons: Slight complexity
2. **Only use touches array** - Pros: Simple Cons: Fails for touchend events

**Decision**: Check changedTouches first, fall back to touches array

**Rationale**: Touch events specification states that touchend events contain touch data in changedTouches (since touch is no longer active). This fix aligns production code with web standards.

**Trade-offs**: Minimal complexity increase for correct behavior across all touch event types

---

### Decision 2: Pre-Push Hook Optimization Strategy

**Context**: Full test suite takes 5+ minutes, blocking developers from pushing code

**Options Considered**:

1. **Run full test suite** - Pros: Complete coverage Cons: Too slow, developers use --no-verify
2. **Type check + fast unit tests only** - Pros: Fast (~30s), catches most issues Cons: Misses integration issues
3. **No pre-push hook** - Pros: Fastest Cons: No quality gate before push

**Decision**: Type check + fast unit tests with option to skip via SKIP_TESTS=1

**Rationale**: Balances speed and quality. Most issues caught quickly, CI runs full suite anyway. Developers less likely to bypass when hook is fast.

**Trade-offs**: May miss some issues locally, but CI catches them before merge

---

### Decision 3: Security Features Scope

**Context**: Needed to enhance user trust and meet compliance requirements

**Options Considered**:

1. **Minimal (just authentication)** - Pros: Fast to implement Cons: Insufficient for trust
2. **Comprehensive (auth + privacy controls + data export)** - Pros: Full compliance, user trust Cons: More implementation time
3. **Third-party identity provider only** - Pros: Less code to maintain Cons: Vendor lock-in, less control

**Decision**: Comprehensive security features with Supabase authentication

**Rationale**: GDPR compliance requires data export and deletion. Building trust requires visible security indicators. Supabase provides authentication infrastructure while we control privacy features.

**Trade-offs**: More code to maintain, but essential for user trust and legal compliance
