```typescript
// Conflict resolution with last-write-wins strategy
export async function resolveConflict<T>(
  local: T & { updated_at?: string },
  remote: T & { updated_at?: string },
  strategy: ConflictStrategy = 'last-write-wins'
): Promise<T> {
  if (strategy === 'last-write-wins') {
    const localTime = new Date(local.updated_at || 0).getTime();
    const remoteTime = new Date(remote.updated_at || 0).getTime();
    return remoteTime > localTime ? remote : local;
  }
  return local;
}
```

## Technical Decisions

### Decision 1: Supabase Anonymous Authentication over Traditional Auth

**Context**: Needed to enable cross-device sync without requiring explicit user registration upfront.

**Options Considered**:

1. **Traditional Email/Password Auth**: Pros: More secure, explicit user accounts. Cons: High friction, reduces conversion.
2. **Anonymous Auth with Optional Upgrade**: Pros: Zero friction, progressive enhancement. Cons: Requires careful session management.

**Decision**: Anonymous Auth with Optional Upgrade (Plan A)

**Rationale**: Prioritizes user experience by eliminating registration friction while maintaining ability to sync data. Users can upgrade to permanent accounts later without data loss.

**Trade-offs**: Slightly more complex session management and device identity handling, but significantly improved user onboarding experience.

---

### Decision 2: Last-Write-Wins Conflict Resolution Strategy

**Context**: Multiple devices could modify the same data while offline, requiring conflict resolution.

**Options Considered**:

1. **Last-Write-Wins**: Pros: Simple, predictable. Cons: Can lose data in edge cases.
2. **Operational Transformation**: Pros: Preserves all edits. Cons: Complex implementation, higher overhead.
3. **Manual Resolution**: Pros: User control. Cons: Poor UX, requires user intervention.

**Decision**: Last-Write-Wins with timestamp comparison

**Rationale**: Game progress data is typically linear (scores, achievements), making complex merging unnecessary. Simplicity ensures reliability and performance.

**Trade-offs**: Potential data loss in rare simultaneous edit scenarios, but acceptable for game state use case.

---

### Decision 3: CSS Strategy - Keep Vanilla CSS, Add Tailwind Gradually

**Context**: Needed to improve styling maintainability while avoiding massive refactoring.

**Options Considered**:

1. **Full Tailwind Migration**: Pros: Modern, utility-first. Cons: Large upfront refactoring cost.
2. **Vanilla CSS Only**: Pros: No changes needed. Cons: Maintainability issues persist.
3. **Hybrid Approach**: Pros: Gradual migration, low risk. Cons: Mixed paradigms during transition.

**Decision**: Hybrid approach with Tailwind for new components

**Rationale**: Allows incremental adoption of Tailwind without disrupting existing functionality. New features use Tailwind, legacy code remains stable.

**Trade-offs**: Temporary style inconsistency and dual build pipeline, but manageable technical debt.
